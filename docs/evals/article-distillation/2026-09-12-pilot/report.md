日期：2026-09-12。目标：验证隔离生成、两阶段盲评与汇总流程，不以本次小样本判断整体效果。

同一份合成正文、同一规划任务，新旧版本各独立生成一次。未参与生成的评审在不知道版本身份的情况下，先保存产物复述，再读取原文评分。

盲评结果：平局。两组均保留调查循环、人的批准权、未批准不写入、工具失败不显示完成、有界任务不等于短时任务，以及模拟数据的证据边界。章节组织与措辞存在差异，但不足以跨越评分等级。

本次没有证据支持“新版总体更好”，也没有发现该案例中的退步。不能把两个满分解释成实际页面已经清晰；本次产物仅为规划。

## 可追溯材料

- source.md：固定正文，明确标为合成测试材料。
- baseline-skill.zip / candidate-skill.zip：实际提供给两个生成者的完整版本快照。
- manifest.json：每个文件和快照哈希、运行条件、任务、揭盲映射。
- A.md / B.md：匿名首次产物，未接受评审反馈或修订。
- reader.md：评审未读原文时保存的原始复述。
- blind-judgment.json：评审原始匿名判断。
- judgments.json：协调者加入案例、范围、版本映射的评分数据；评分未修改。
- summary.json：汇总脚本的实际输出。

生成者使用全新上下文，只获各自 skill、正文和输出位置；两者均被要求仅规划、不调用其他代理。评审另起全新上下文，第一阶段只读 A/B，第二阶段才提供正文和评分尺度。文件读取范围由指令限制，不是文件系统安全沙箱。未指定模型覆盖，均继承父代理；准确模型 ID 和推理参数未暴露在运行元数据中，因此不声称严格受控的模型实验。

## 对评估机制的独立审查

另一个未参与实现的 subAgent 只读审查了 skill、评估协议、样例和脚本，发现三项重要缺口：

1. 未向生成者明确冻结阶段，HTML 任务可能先经历独立反馈后才交付。
2. 初始案例全部是规划，无法评估落地能力。
3. 汇总混合规划/HTML、开发/保留集，可能掩盖局部退步。

已修正：统一在通常自检后、外部验收前冻结；新增开发集与保留集 HTML 案例；汇总按 scope/split 分组并记录各案例次数及退步。原审查者定向复核后三项关闭，未发现新增阻断或重要问题。这是对评估机制的审查，不是文章效果证明。

试跑快照形成于这些评估协议修正之前；其文章生成规则与本轮最终 SKILL.md 相同。保留实际快照而非事后替换，确保原始试跑可追溯。

Skill 官方格式校验通过；引用路径、五个案例的输入存在性及补丁格式检查通过。汇总工具已验证匿名映射、范围分组、缺失数据处理、无法比较记录不进入均值、退步记录、非法评分与缺少证据拒绝，并已处理本次真实盲评记录。

本次只跑一个开发集规划案例，每版一次。未运行其余四个案例、保留集、HTML 渲染及独立验收修复闭环，未测量修复成本。短合成材料已经明确表达关系，可能不足以区分两个成熟版本；后续应使用更长且关系分散的固定正文，并覆盖多次生成。不能为获得胜出而改写本次结果或重复试跑直至获胜。
