# Codex 作为平台笔记验收

日期：2026-09-12

## 本轮目标

根据用户反馈，将页面从“依次罗列 Agent 循环、职责边界、集成层和案例”重构为一条连续论证：

> Codex 提供执行内核，业务应用提供工作现场 → 业务界面注入真实上下文 → Agent 调查并提出建议 → 有后果的动作由人批准 → 结果回到业务记录。

内容依据 OpenAI 文章 [Codex as a platform: build on the open agent harness](https://developers.openai.com/blog/codex-as-a-platform)，作者 Nicolas Bonamy、Derrick Choi，发布于 2026-08-19。正文、小标题、Figure 1/2 图注和案例数据作为论据；网站导航与推荐阅读未纳入。

## 内容与证据对应

| 归纳观点 | 机制关系 | 原文位置 | 条件与限制 |
| --- | --- | --- | --- |
| Codex 提供执行内核，业务应用提供工作现场 | Harness 负责状态、工具、沙箱与审批；宿主应用负责界面、业务上下文和控制 | 引言；The reusable part is the agent loop；Figure 1 | “执行内核 / 工作现场”是阅读归纳 |
| Agent 应进入既有界面 | 界面给出当前对象、业务数据和可用动作，结果返回记录系统 | Build software around the workflow；Build beyond the obvious | 不是要求所有产品采用同一种界面 |
| 有后果的动作必须保留人的控制 | Agent 可以调查和建议，写操作先等待批准；批准后工具写入并刷新视图 | Example: Relay；Figure 2 | Relay 使用虚构种子数据 |
| 接入方式取决于交互和控制需要 | `codex exec` 处理有界非交互任务；SDK 提供程序化接口；app-server 让产品直接控制生命周期 | Choose the right integration layer | 不是能力排名，也不按任务耗时划分 |

## 语义验收

- 核心结论首先说明 Codex 与业务应用的互补职责，不再要求读者自行拼接两个独立章节。
- 唯一主图从现有业务界面开始，以节点包含关系标出 Codex Harness；蓝、灰、棕三种边框配合文字图例区分 Codex、业务应用与人的职责，不只依赖颜色。
- Harness 内部用实线箭头表示理解—行动—观察，用带边框的返回路径将未完成或失败结果连回起点；完成后的数据读取与建议从容器向下继续。
- 审批节点具有两个独立出口：“否 / 未批准”明确不执行写入；“批准”才连接 MCP 写操作。记录更新后由回流标签连接到业务视图与用户控制。
- “为什么不是聊天框”使用状态对照解释界面的机制价值；集成层和 Relay 下移为实施选择与案例验证，不再与核心机制争夺层级。
- `codex exec` 已由“短时”改为“有界任务 · 非交互”，忠实保留原文范围。
- 开放源码的正向价值已进入主阅读路径：开发者可以检查应用与模型之间的执行层，并按产品需要调整集成。

## 修正历史

1. 原页面把 Agent 循环、职责边界和 Relay 分成三张独立图，读者需要自行重建联系。本轮合并为一张端到端系统图。
2. 原 Agent 循环与 Relay 主要用文字加 `↺` 表示返回。本轮用实际边框路径和独立分支表达失败回流、拒绝与批准结果。
3. 首轮重构的 390px 检查发现“提供当前对象、历史、规则与目标”随箭头整体旋转，产生竖排文字；已改为只旋转箭头并重新截图。
4. 原验收截图没有完整覆盖手机审批出口。本轮增加独立的 `branch-mobile.jpg`，只在截图可见范围内记录验证结论。
5. 根据用户反馈，将左侧导航与各节 eyebrow 统一为完全相同的标签；H2 继续负责表达该节的完整结论。

## 残余限制

没有用户指定的像素参考，因此系统图是概念重构，不是 OpenAI 原图复刻。未进行跨浏览器覆盖，也未复现 ARC-AGI-3 或税务试点。桌面图的记录回流以底部向上箭头和明确文字表示，没有绘制一条跨越整张画布返回首节点的长线，以避免穿过节点；该取舍已在图注中说明流向。

## 中文与术语

- 沿用 “Harness”，在本文语境中以“执行内核”解释其可复用职责，避免译为容易让人想到一次性模板的“脚手架”。
- `agent loop` 译为“Agent 循环”；图中用“理解任务—推理与行动—观察结果—返回继续”还原它的实际动作。
- `app-server`、`codex exec`、Codex SDK、MCP 保留产品或协议名称，并用职责说明补足含义。
