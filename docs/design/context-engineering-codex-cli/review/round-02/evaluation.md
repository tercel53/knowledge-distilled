## 问题定位、归因与严重度

### 1. [重要] 隔离微图把“一分为二”排成单行串联

- **原文依据：** Strategy 4 定义 Isolate 为把工作分到 separate context windows；文中子代理例子强调不同子任务不共享完整上下文，而不是窗口 A 的内容再流入窗口 B。
- **骨架要求：** content-plan“图解任务”要求 `共享上下文 → 窗口 A/B`，即同一来源到两个独立边界。
- **页面位置：** `#model`；`index.html` 第 39 行；布局规则在 `note.css` 第 2 行 `.split-flow{display:flex...}`。
- **桌面与手机证据：** 两个视口都显示 `共享上下文 ↘ 窗口 A ↗ 窗口 B`；第二个箭头的起点在视觉上紧接窗口 A，形成 A → B 的链条，没有共同分叉点、上下两支或分别指向 A/B 的两条线。
- **读者证据：** 新读者把它复述为“共享上下文分成窗口 A、窗口 B”，但该首遍受后文文本污染，不能据此排除几何歧义。
- **归因与影响：** 产物图形表达问题，不是原文、骨架或读者遗漏。它影响 K2/K4 中隔离的核心关系，可能把“不共享”画成两个窗口串联共享。
- **建议：** 让“共享上下文”连接一个真实分叉点，再用两条独立线分别指向窗口 A 和窗口 B；或在移动端改为共享节点上方、A/B 并排在下方。不要仅用两个对角箭头字符夹在三个横向节点间。修复后在桌面与 390px 同区域复核端点和方向。

### 2. [重要：验收缺口] 新读者图解首遍仍受后文与题目暴露污染

- **位置：** Round 02 reader.md“读取范围、初始状态与污染说明”。
- **归因与影响：** 阅读任务/浏览器材料暴露方式。内容产物并未导致污染，但角色门槛要求首遍证据隔离，故当前不能用该记录证明普通读者只看图解即可恢复完整主线。
- **建议：** 修复隔离分流后，以截图文件或只包含标题、主图、图例和邻近短说明的独立材料交给全新读者；不要先打开整页 DOM/可访问文本。保留 Round 02 记录，不覆盖。

### 未确定项：来源更新时间

- 当前 Chrome 新请求为 2026-09-10，主协调者网页抓取为 2026-09-09，本地产物为 2026-09-09。
- 因两个来源工具给出不同结果，当前状态为**未确定**，不作为需修正项。若未来需要统一，可保存同一时刻的响应正文/缓存头或由用户指定采用哪个版本日期。
