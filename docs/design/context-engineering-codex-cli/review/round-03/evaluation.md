## 隔离图专项复验

### 结构与方向

当前 HTML 的隔离关系为：

`共享上下文` → 中央竖向主干 → 水平分叉 → 两条分别向下的箭头 → `窗口 A` / `窗口 B`

两条支路在真实分叉点之后独立落到 A、B；A 与 B 之间没有连线、箭头或顺序编号。无障碍标签为“把共享上下文拆分为窗口 A 和窗口 B 两个独立边界”，与视觉关系一致。邻近文字进一步把语义限定为“不共享全部内容”，而不是窗口间传递。

### 桌面 1365×900

- 四张动作卡在同一主图中以 2×2 网格呈现，隔离卡完整可见。
- “共享上下文”、分叉主干、水平叉线、两枚向下箭头与 A/B 节点全部清楚；箭头不穿过标题、节点文字或卡片说明。
- 实测隔离流区域约为 368×96；共享源位于上方中央，主干 12px；A/B 节点各 72×31，左右并列且间隔明确。
- 页面 `scrollWidth = innerWidth = 1365`，无横向溢出。

### 手机 390×844

- 四张卡改为单列，但卡片前的短句仍明确排除固定流程；动作方向箭头未被隐藏。
- 隔离卡宽约 320px，分叉流区域约 282×96；共享源、中央主干、水平叉线、两条向下箭头和 A/B 节点均完整落在卡片内。
- A/B 节点仍左右并列，没有变成 A→B；文字、连接线与箭头无覆盖。
- 页面 `scrollWidth = innerWidth = 390`，无横向溢出。
- 手机无法在单个 844px 高视口中同时看到全部四卡和底部 `≠` 图例，需要连续滚动；读者将其记录为“准确但需要额外整理”，没有造成错误理解，属于合理的响应式阅读代价，而非阻断问题。

### 独立读者证据

Round 03 读者对隔离图的冻结复述是“一份原本共享的上下文被分到窗口 A 与窗口 B 两个分支，而不是信息从 A 再流向 B”；桌面和手机均作出相同判断。这个复述与当前图形完全一致，也说明 Round 02 的串联歧义在产物层面已经消失。

不过，浏览器在读者首次打开及每次重载时自动返回整页无障碍文本，提前暴露了后续正文、自测题和来源区。污染发生在视觉首遍冻结之前。即使读者随后自觉只依据截图范围书写，评估者仍无法证明其复述未受后文影响。因此该记录只能作为**受污染但支持性的观察**，不能满足 evaluator 对“独立首遍”的硬门槛。

## 完整主线与阅读顺畅度

正文形成连续主线：

1. 有限上下文造成信息供应问题；
2. Write / Select / Compress / Isolate 分别改变信息去向、载入范围、表示长度与共享边界；
3. 四种操作按任务组合，而非按固定顺序执行；
4. Codex CLI 机制分别承载四类操作；
5. 提示工程、上下文工程、Harness 工程是三个职责层次；
6. 机制存在、作者映射、效果数字与实践清单具有不同证据强度。

读者第二遍补出了外部状态会过时、压缩有损、隔离有协调成本、独立上下文不等于安全隔离等限制；其全文后五问均无需借助答案才能形成正确的主线。四张组合卡给出了可复述的互补关系，Harness 区用三个并列层级分别说明“一次请求怎样表达”“每次推理能看到什么”“怎样让这些决策持续发生”，未再把三层压成一个含混口号。

术语方面，`schema`、MCP、profiles、OS sandbox 对完全不熟悉 Codex 的读者仍有学习成本，但页面给出了足够的功能性解释；该笔记本来就省略具体配置教程，所以这属于范围边界，不是信息断裂。
