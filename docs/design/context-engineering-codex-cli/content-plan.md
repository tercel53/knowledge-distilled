# 内容计划：Codex CLI 上下文工程

## 五问

- 问题：编码 Agent 的失败常被误判为提示词措辞问题，实际也可能是它没有看到完成下一步所需的信息，或窗口被无关信息占满。
- 结论：用写入、选择、压缩、隔离四类操作持续管理上下文；Codex CLI 的若干机制可按这四类理解。
- 机制：写入提供外部持久状态；选择控制读入的相关性与时机；压缩缩短当前表示；隔离把内容与能力分到不同边界。两两组合补足单一动作的缺口。
- 依据：作者将 LangChain/Sourcegraph 框架映射到 Codex CLI v0.139 功能，并引用官方文档、行业指南与第三方基准。属于观点/实践综述，而非统一条件下的受控实验。
- 边界：具体配置随版本变化；效果百分比和 token 阈值缺少充分实验条件；实践清单不是必要条件，隔离也有协调成本。

## 连续解释

为避免 Agent 只完成当前窗口看得见的部分，作者提出不要只优化单次提示词，而要管理整个信息环境。四个动作分别改变信息的去向：把关键状态写到窗口外，在下一步需要时选择性读入，对趋满窗口压缩并保留重点，把不必共享的任务、工具和文件隔离到不同边界。它们不是固定时序；组合后，外部状态可以在压缩后恢复，完整目录可以按需加载，各子任务也只接触自己的上下文。文章对 Codex 机制的描述有官方资料支撑，但对效果幅度与 token 阈值的证据不足以普遍外推。

## 图解任务

- 主图问题：四个动作各自怎样改变有限上下文的信息流？对应 K2/K4。几何：四个独立微型信息流分别画出当前窗口→外部状态、外部资料→当前窗口、较长内容→较短表示；隔离使用共享源、真实分叉点和两条独立支路指向窗口 A/B。在桌面与手机都保留方向。短说明解释四个动作不是时序。
