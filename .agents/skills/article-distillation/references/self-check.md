# 静态自评题与参考答案

帮助读者先用自己的话解释，再对照依据发现缺口。自评不是考试或学习效果认证；理解作者不等于赞同作者，不要求复述唯一措辞。

## 从理解点出题

沿用内容骨架中的证据对应表，增加题号、所检验的理解点和笔记回查位置即可，不另建第四份笔记或强制 JSON 协议。分别保留笔记锚点与原文章节定位，不能把本地章节对照链接当成原文链接。

- 主线与机制：检查方法通过什么过程解决原来的困难，而非只复述结论。
- 边界与误解：用具体的过强结论，检查读者是否保留条件、代价和未知。
- 轻量迁移：改变一个已讲解的条件，让读者据此调整判断。明确新情境是辅助假设，给齐必要条件，不额外考察陌生专业知识。

一般提供 3–5 题，按文章复杂度减少或调整，不要求每类凑足一道。每题应能用几句话作答，避免把多个复杂任务捆在一起。原文证据不足时，参考答案说明能判断到哪里，不补造确定结论。

| 不适合的题目 | 更有价值的题目 | 区别 |
| --- | --- | --- |
| 作者列出哪三类工具？ | 工程规范已写进文档，Agent 仍引入违规依赖。仅把文档写得更长是否足够？为什么？ | 检验可查阅的规则与可执行检查之间的机制差异。 |
| 本文对你有什么启发？ | 能否从这个团队的成功推出所有项目都适合相同合并策略？还缺什么条件？ | 检验结论边界，不评判个人感想。 |
| 换个场景怎么做？ | 假设 Agent 能读代码和文档，却看不到运行结果。能否仅凭完成代码修改就确认问题已修复？缺少什么？ | 给定具体变化，检验观察与验证的关系。 |

以上示例只适用于正文确实讲过相应机制的文章，不能作为每篇固定题库。

## 淘汰低诊断价值题目

逐题检查并改写或删除：
- **泄露答案**：题干已告诉读者应采用哪个结论，只要求复述。
- **重复检查**：不同措辞检验同一理解点，没有新增误解目标。
- **材料不足**：依赖正文未讲的条件或陌生领域知识。
- **假唯一答案**：原文容许多种合理判断，答案却无条件只认一种。

每题有可辨认的误解目标即可，不要求同时覆盖机制、边界和迁移。证据不足时允许“仅凭本文不能确定”，并说明缺少的条件。

## 每题展开后的内容

1. **参考解释**：回答问题并说明关键推理，保留条件；不是一句关键词。
2. **对照要点**：指出回答应包含的含义，避免重复一遍完整答案。
3. **容易误解**：指出与本题有关的遗漏、概念混淆或过度外推。
4. **回查位置**：链接笔记解释，并给原文链接与章节名。原文没有可靠锚点时使用原文 URL 加明确章节标题，不编造定位。

四项内容各司其职，避免重复成长文；接受正确改述与有依据的不同判断。答案是依据正文整理的参考解释；补充场景、推论须明示。读者准确说明作者的观点与依据后可以持不同意见。

## 先检查材料，再交付自评

逐题核对：原文是否支持答案？理解稿是否已讲解回答必需的知识？新场景是否给出足够条件？题目是否有歧义或暗示唯一立场？主线或关键边界是否漏检？

不能只根据摘要出题，否则摘要与题目可能共同漏掉关键条件。发现正文缺口，先补正文或改题；不要把答案区作为核心机制的首次讲解。将逐题依据、讲解位置和修正记录并入本轮内容计划与验收报告。

## 展示边界

问题始终可见，答案以原生 `details` / `summary` 独立折叠且初始不带 `open`。使用“参考答案”“对照要点”，提示先回答再展开。无需答题表单、提交、顺序锁、成绩、阅读进度或个人状态；不因点击展开而标记“已学会”。Markdown 使用同样的折叠语义，保证内容在 GitHub 可读。

折叠与回查可用键盘操作，长标题和来源可换行。页面关闭 JavaScript 后仍能阅读问题与展开答案。已有深链接脚本可用于回查折叠章节，无需为自评新增专用脚本或 AI 接口。


## 结构检查的证据边界

新建或实质修改自评时，保留唯一稳定题号并同步 HTML 与 Markdown；问题位于答案折叠容器之外，每题有独立且非空的 summary，初始不得有 open 属性（open="false" 也会展开）。逐题检查回查目标存在、来源无占位符、两种产物题号和题干对应。

先确认校验脚本实际覆盖哪些要求；未自动覆盖的项目须手动核查，不能因脚本通过就视为已检查。静态结构不能证明答案正确、CSS 未隐藏题目、JS 未自动展开、键盘或无 JS 可用，这些仍需语义和浏览器证据。旧文未改部分不强制迁移标记。
