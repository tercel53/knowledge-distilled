# 质量原则与执行分层

这些原则是文章蒸馏的稳定约束。主 Skill、图解、读者和评估者文件负责各自阶段的执行细节，不重复定义另一套通过标准。遇到局部规则冲突时，优先保证以下不变量，再按当前任务范围选择最低充分流程。

## 五个质量不变量

1. **来源忠实（Source Fidelity）**：结论、机制、证据强度、主体、条件和未知不能超出已读取原文。阅读归纳、辅助解释和应用建议必须与作者原意区分。
2. **论证可恢复（Argument Recoverability）**：读者应能恢复文章的核心问题、结论、关键连接与影响结论的边界；不能只认出主题、节点或章节名。
3. **视觉语义忠实（Visual Semantic Fidelity）**：图中的位置、包含、箭头、分支、循环、面积和线型不得暗示原文没有的时序、因果、充分性或定量关系。没有图时此项不适用。
4. **渐进展开（Progressive Disclosure）**：默认层提供形成核心理解所需的信息，展开层补证据、例子和细节；关键前提或核心连接不能首次藏在折叠内容、答案区或制作方口头说明里。
5. **独立验证（Independent Verification）**：当任务采用深度入库或用户明确要求独立验收时，制作方自检不能替代独立读者与评估者；标准入库不为了形式完整自动启动重型独立验收。

## 选择最低充分执行强度

按用户要求、文章复杂度、长期价值和错误代价选择，不因“更完整”自动升级：

| 档位 | 适用场景 | 默认产物 | 默认验收 |
| --- | --- | --- | --- |
| 轻量蒸馏 | 探索式阅读、快速理解、普通总结 | 回复或单份 Markdown | 来源核对、论证骨架自检 |
| 标准入库 | 明确要求进入知识库，文章结构清晰、错误代价普通 | HTML、README、metadata、content-plan，必要图解/自评 | 内容自检、结构校验、桌面/手机浏览器检查 |
| 深度入库 | 核心长期知识、复杂/高争议论证、重要参考图、高错误代价，或用户明确要求严格验收 | 标准入库全部产物及独立验收记录 | 标准验收 + 独立读者 + 独立评估 + 必要修正复读 |

从轻量升级到入库时复用已确认骨架；从标准升级到深度时复用现有产物与自检证据，不重新制造无关中间材料。用户明确指定产物或验收范围时，以用户要求为准。

## 先识别文章的认知形态

不要假设所有文章都适合“总览图 + 短说明”这一种表达。先判断主要认知形态，可混合：

- **概念 / 方法框架**：突出概念关系、职责和适用边界。
- **系统 / 架构解释**：突出组成、输入输出、依赖和控制边界。
- **工程实践 / 经验报告**：突出初始限制、设计变化、观察、代价和可迁移边界。
- **研究 / 实验结果**：突出问题、方法、对照、指标、结果与限制。
- **数学 / 形式论证**：优先保留定义、假设、推导依赖和结论成立条件；图只辅助结构，不要求替代必要推导。
- **方案比较 / 决策分析**：突出共同目标、可比条件、维度、取舍和不确定性。

图解强度和验收方式服从认知形态。主题本身复杂不等于产物失败；只有当必要关系可以更直接表达却仍要求读者自行补推理时，才归为表达问题。

## 评估 Skill 是否真正改进

版本比较优先看：内容准确性、核心关系恢复、阅读负担、结构/视觉阻断问题，以及执行成本（工具调用、上下文材料、修复轮次）。若现有评估工具不能可靠测量某项，明确标为未测量，不用主观印象补分。目标不是追求规则数量或最重流程，而是在较低阅读与执行成本下保持可靠理解。
