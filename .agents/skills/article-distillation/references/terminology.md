# 上下文术语管理

术语库服务于后续文章蒸馏时的表达判断。它保存的不是“英文 → 中文”的固定映射，而是“概念 → 各文章语境中的具体含义与选词理由”。读者页面不需要因此增加术语页或双向链接。

## 何时查询

正文出现以下术语时，在定稿前查询 `terminology.json`：

- 术语直接参与核心论证；
- 直译容易丢失在流程中的作用；
- 同一个英文词可能因文章语境而改变含义；
- 仓库中其他文章很可能已经使用过该概念。

使用脚本可避免手工翻找 JSON：

```bash
python3 .agents/skills/article-distillation/scripts/terminology.py term "product spec"
python3 .agents/skills/article-distillation/scripts/terminology.py article "harness-design-long-running-apps"
python3 .agents/skills/article-distillation/scripts/terminology.py validate
```

`term` 同时匹配概念 ID、英文原词、中文推荐表达、历史实际译法和避免表达；`article` 匹配文章路径、标题与来源 URL。结果提供来源 URL、本地章节定位及核对状态。查询无结果时回到原文独立判断，不代表该词不存在或不可使用。

## 如何判断与复用

1. 先读本篇术语所在段落，说明它在当前论证中承担什么作用。
2. 查询同一术语的历史用法，比较对象、流程位置、范围和限定条件。
3. 含义相同时优先沿用既有中文表达；含义不同时允许使用不同译法，并记录差异原因。
4. 正文首次出现时可保留英文原词或给一句短说明；后文使用自然、稳定的中文表达。
5. 避免只因字面对应而复用历史译法，也避免为了显得专业而保留不必要的英文。

当前原文优先于历史记录。`preferred_zh` 仅在 `scope` 所述含义下推荐；每条 `avoid` 的 `scope` 指明何时不推荐该表达，不能将“产品规格”“硬阈值”等列为全局禁用词。相关词不自动等于同义词，例如 scaffold 不直接作为 harness 的别名。

每个用法的 `review` 分开记录两种状态：`source` 为 `verified` 或 `pending`，表示是否实际核对原文；`wording` 为 `user_confirmed`、`reviewed` 或 `pending`，表示措辞确认情况。`note` 说明核对依据或待解决的问题。用户认可中文自然不等于已核对原文；迁移旧记录时，不凭已有笔记补记已核对状态。

## 何时沉淀

只收录会改变读者理解、容易误译或有明显复用价值的术语，不收录每个工具名和普通名词。新增或修订条目时维护：

- `id`：概念层面的稳定 ID；一个 ID 对应一种含义。相同拼写但不同概念应拆成不同 ID。
- `source_terms`：原文词形与常见变体。
- `preferred_zh`、`definition`、`scope`：默认表达、概念定义及适用范围。
- `usages`：每篇文章的标题、路径、原文位置、该语境中的含义、实际译法及选择理由。
- `usages[].local_anchor`：对应笔记的 HTML 章节 ID，供查回本地上下文；不是外部原文的锚点。
- `usages[].review`：原文核对与措辞审读状态，以及判断依据。
- `avoid`：已经验证为不准确或容易误解的表达，以及原因。

每个文章用法必须带 `article_path` 和 `source_location`，并用 `context_meaning` 记录局部语义。不要只登记“这篇文章出现过该词”。完成后运行 `terminology.py validate`，检查 ID、文章路径和双向查询所需字段。

原文位置优先记录小标题和段落线索；无法确认外部锚点时保留 URL 与文字定位，不构造链接。脚本仅验证数据与定位结构，不能证明语义正确。

## 回写与纠错

在原文核对和中文审读后更新有复用价值的记录，并如实填写状态。暂不能核对的解释保留 `pending`，下次使用时优先回查来源。已知只是表达偏好时，不把它升级为概念定义。

纠正旧解释时，在该用法的 `review.note` 保留原表达、修订理由与依据，更新日期；查询同概念的其他文章用法，逐一判断影响。处于本轮编辑范围内的文章同步 HTML、Markdown 和元数据；范围外的受影响文章在交付中指出。不同语境不能批量替换。双向关系始终由同一份 `usages` 记录查询得到。

## 与文章文件的关系

术语库集中保存跨文章的语义记录，是蒸馏流程的内部参考。HTML、Markdown 和 `metadata.json` 仍按文章实际内容维护；除非用户明确要求面向读者展示术语关系，否则不向页面增加术语索引、反向链接或额外导航。
