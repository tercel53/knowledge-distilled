# 图解选择与视觉验收

## 先固定图的解释任务

在已有 content-plan.md 为每张主图记录一行：图要回答的问题 / 对应 K 点 / 必须显式的关系 / 几何表达什么 / 必要短说明 / 详细区补什么。不另建图协议。一图承担一个明确任务，数张图可连续讲通主线。

实现前对主图做一次关系预检：逐条列出每根箭头的起点、终点与含义，确认并列、汇聚、分支、循环没有被画成错误时序；同时写明桌面布局和手机重排后这些端点如何保持。预检未通过不进入独立读者验收。

## 根据关系选图

| 读者需要理解的关系 | 图形方式 | 避免误读 |
| --- | --- | --- |
| 多个条件共同支撑某项能力 | 多路汇聚、容器与中心节点 | 汇聚表示共同支撑，不自动表示充分条件 |
| 知识组织、目录与索引 | 树、分支、入口与引用连接 | 标明是在查找、依赖还是汇总，别画出不存在的执行顺序 |
| 检查与不同结果 | 菱形判断、标注条件的分支 | 通过与失败都应有去向；重试返回正确节点 |
| 观察与迭代 | 有向循环与退出路径 | 明确返回哪里、何时退出、何时由人判断 |
| 随时间发生的变化 | 时间轴或阶段图 | 并列主题不能冒充时间顺序 |
| 方案比较与代价 | 对照图、维度表或有根据的坐标图 | 不虚构评分、比例与连续数值 |
| 原因与后果 | 因果链与条件注释 | 只有相关性时不要画成已证实的因果 |

图形可以组合。数量由信息决定，不要求每个段落都配图。小表格若已能清晰比较，不必强行改图。

## 从内容到几何

先写出读者应从图里看见的机制或变化，再确定节点与连线。区分“作者如何论证”和“系统如何执行”：并列原则不能画成强制步骤；阅读归纳应标明，不能用几何关系补出原文没有的因果或依赖。

针对机制选择可识别的视觉载体。例如：

| 要解释的机制 | 可用的视觉表达 | 无效替代 |
| --- | --- | --- |
| 过滤无关工具输出 | 同一张表的整表回传与所需列回传对照 | 三个写着“假设／问题／替代”的长文本框 |
| 按需选择上下文 | 全部正文预装与索引选中、加载正文对照 | 仅列出 Skills、上下文编辑、子代理名称 |
| 跨窗口延续记忆 | 当前与后续窗口间的保存／读取路径，替代方案并列 | 把并列机制画成必须串行的步骤 |
| 模型升级使补偿失效 | 对齐旧问题、原补偿和新能力下的状态 | 只展示静态职责分层 |

这些是视觉语义示例，不是固定图形模板。单元格数量、面积、宽度等没有定量依据时，应标为示意；对比中用形状、标签或线型辅助区分，不能仅依靠颜色。

再写出节点及连线含义，最后布置位置。例如：

- 人 → 环境：建设。
- 环境里的若干机制 → Agent：提供支撑。
- 交付中发现的问题 → 环境：持续改进。

这里的箭头不是同一种含义，应通过位置、标签或线型加以区分。过程箭头使用实线，反馈可以使用虚线，但仍须文字说明；颜色只能辅助。

把标题、正文和图的职责分开：
- 标题说结论。
- 图表达关系。
- 辅助说明解释原因和证据。
不要把完整句子原样复制到多个大框里，形成另一堵文字墙。保留短标签和图例，暂时遮住长解释：若位置、连线、包含或状态变化不能帮助读者理解关系，应重画，而非再加段落。

比较图须显式呈现哪条关系增加、删除或改变，不能只换颜色。未经定量证明，不以面积、粗细或比例暗示测量值，必要时标“示意”。

默认状态保留读懂图所必需的前提、简短证据与关键限定，并与对应主张就近呈现，末尾边界区仅作汇总。例如“仅在有回归测试时可自动合并”应紧邻合并路径，不能只在折叠详情里说明。详细推导和扩展来源可折叠，但不能让读者必须逐个展开后才能组装出文章主线。

关系词必须落实为几何关系，不能只在文本里写“循环”“分支”“回到”，或用单个 `↺`、`→` 符号代替：
- 循环线应从结果实际返回正确节点，同时保留完成或退出路径。
- 条件分支应有独立的条件标注、连接线与结果节点；只适用于其中一支的后续动作不能从两支共用的容器继续连接。
- 职责边界要由分区、容器、图例或线型表达，不能只靠相近文案让读者猜测所有者。
- 重排断点后重新推导连接方向。若箭头旁有文字，只旋转方向标记，不旋转承载文字的整个容器。

使用库内已有图标；仅为纯结构图编写 SVG 节点和连线，不用手绘路径伪造品牌标志或装饰插画。SVG 应包含可理解的 title/desc 或等效替代文本。说明内容较多时用 HTML 保证换行和可访问性。

## 响应式策略

优先让图在可用宽度中保持主次与关系：
- 宽屏图文并排；窄屏图在前、解释在后。
- 三路汇聚若仍可读，可以保留；过多节点则按组展开、局部拆图或提供可操作的缩放。
- 字号小到必须放大才能识别主要节点时，重排图，而不是继续压缩。
- 反馈线由节点位置确定；修改文案或断点后重新检查，不假定固定高度仍正确。
- 原文对照折叠时，锚点导航先展开再定位。图中可以跳到证据，但不要把章节编号链接到不相关位置。

## 语义验收

在浏览器默认阅读状态执行，并与排版及交互检查分开记录：

1. 从标题、图与必要短说明，复述图表达的机制或变化；指出图中哪处几何关系承担了这个解释。若只能复述节点名称，图还没有完成解释任务。
2. 对照原文，检查图中箭头究竟表示调用、读取、推导还是反馈；确认没有把并列原则误画成时序，也没有把相关性改成因果。
3. 折叠详细文字后，检查关键前提、关系和影响结论的限定是否仍可见；展开后应补充证据与细节，而不是首次揭示核心机制。
4. 在手机重排后再次复述关系，确认并列通路没有变成串行，箭头方向与实际节点位置一致。

记录具体断点和修正，不能仅写“图形优先已通过”。这些检查不要求额外用户审批；由当前任务完成核对。

## 验收记录

在仓库规定的设计目录中记录：
1. 本轮目标：用户批准的结构、截图或明确变更要求。
2. 截图：桌面与手机，覆盖关键图、分支、循环和交互状态。
3. 观察结果：字体可读性、节点对齐、箭头方向、图文层级、溢出和遮挡；另记语义验收中关键关系如何由图表达、是否发现推导断点。
4. 交互结果：节点跳转、键盘操作、折叠展开及深链接。
5. 修正与残余问题：只写实际观察和验证过的内容。

桌面与手机检查使用同一份观察矩阵集中完成；修订后优先重截受影响的主图、连接关系和断点，不重复获取与修改无关的整页材料。只在截图工具能稳定保存且截图能直接证明结论时将其列为证据；同一种保存或拼接方式确认不兼容后不反复重试，改用可用的局部截图或如实记录未保存范围。

验收结论必须能被保存的截图直接证明。为每个声称已验证的关键关系建立最小覆盖：总览主线、条件分支、反馈回路，以及桌面和手机重排后的端点。整页截图若截断关系的起点、终点或返回线，应补充同视口下的局部截图；不能用“页面可打开、无溢出”代替关系已经可读，也不能在报告中写入截图没有覆盖的结论。

若用户要求忠实还原指定图片：
- 先读参考，记录尺寸、节点比例、字体、图标、颜色、间距、箭头与反馈关系。
- 对照相同组件区域，不用一张图与整页截图比较；统一尺寸、密度及状态。
- 在同一比较输入查看参考和渲染，修正主要差异后重新截图。
- 只有用户明确要求重设计时，新的结构才成为目标。保留历史记录但标明它不是当前像素基准。

## 本仓库经验

Harness 笔记最后采用总览汇聚图、知识入口图、规则分支图与反馈循环图。不同图形承担不同解释任务，文字仅辅助。三种机制与 11 个原文章节都是该文章的事实结构，不是其他文章必须复制的格式。

此前的问题：
- 按原文标题画路线，只告诉读者“讲了什么”，没有解释结论。
- 多个文字框虽然有箭头，仍要求读者自己推理关联。
- 文字总结已有清晰主线，页面却把机制、职责、案例和接入选项拆成同级模块，导致正确内容重新变成目录。
- 导航短标签与章节眉题使用近义词，增加了没有信息价值的词汇切换。
- 用符号或说明文字声称存在反馈与分支，但几何上没有闭合回路或独立去向。
- 截图未覆盖完整关系，却在验收报告中宣称对应布局与语义已经验证。
- 重复主题映射与主阅读路径竞争。
- 参考图转代码时丢失图标与比例，却只检查功能是否正常。
