Codex CLI 的上下文工程：
写入、选择、压缩与隔离

Context Engineering for Codex CLI in June 2026: The Write-Select-Compress-Isolate Playbook

上下文工程的核心不是塞入更多信息，而是持续决定：什么应被保存、何时读入、怎样缩短，以及哪些内容不该共享同一窗口。

这篇观点/实践综述把 LangChain 的四策略框架映射到 Codex CLI v0.139 的机制。它提供的是组织上下文决策的词汇与操作清单，不是证明某套配置对所有团队都有效的受控实验。

阅读范围：保留四策略的机制、组合关系、Codex 映射和证据边界；省略大部分配置片段与完整引文目录。配置会随版本变化，落地前应回到当前 OpenAI Docs。

01 / 四个动作

四个动作共同管理有限上下文

它们不是依次执行的流程，而是四种不同的信息操作：外存、读入、缩短、分界。

以上为阅读归纳图，不是原文图表。四种操作共同降低信息丢失、噪声占用和任务串扰的风险，但都不是正确性的充分条件。

02 / 信息流

每个动作改变不同的信息流

写入：把易失会话变成可再读状态

当前会话→AGENTS.md / memories / PLANS.md→后续读取

作者把 AGENTS.md 视为操作策略而非背景介绍。重要约定和进度不再只依赖对话历史，因此能跨压缩或跨会话恢复。

代价：外部状态也会过时；写得更多不等于更准确、更容易找到。

选择：需要时才把资料加载进来

完整目录→按任务筛选→相关工具 / 资料

Tool Search、MCP 工具范围和 Web Search 分别在运行时或配置层控制哪些定义与资料进入窗口，处理相关性与时机。

关键：完整信息可以存在于外部，但不必每轮全部预装。

压缩：缩短表示，而不是保证无损

较早历史 / 大 schema→提炼→更短表示

自动上下文压缩摘要较早内容；schema 压缩降低工具定义占用；预算收尾引导促使 Agent 留下当前状态。

风险：摘要可能遗漏精确约定，所以关键状态仍适合写入可复核文件。

隔离：把串扰与访问能力分层阻断

子任务→独立会话→工具 / 权限 / 文件边界

Subagents 分开会话历史，profiles 限定能力，OS sandbox 限制资源访问。三者不是同一种安全保证。

代价：拆分会产生协调与交接成本，简单任务未必值得隔离。

03 / 组合效应

组合使用，才从技巧变成系统

单独使用某个动作只处理一类风险。组合后，写入、选择、压缩与隔离成为四类互补支点；它们按任务需要触发，并非固定路径。

提示工程优化一次请求怎样表达。

上下文工程管理每次推理能看到什么。

Harness 工程用权限、沙箱、事件钩子与多代理协调，让这些决策持续发生。

04 / 证据边界

框架可用，效果强度仍要另行验证

可由官方资料核对的机制

AGENTS.md 层级、memories、自动压缩、子代理和工具范围等 Codex 能力，可在 OpenAI Docs 中找到对应说明。文章把它们归入四策略，是作者的分析映射。

不宜当作普遍阈值的数字

“Tool Search 减少 85–98% 开销”及“100,000 tokens 仍连贯、30,000–40,000 后退化”等数字缺少统一任务、模型、团队和评价方法。它们是风险提示，不是可靠切换线。

“超过两个领域就使用 subagents”、每个里程碑更新 PLANS.md，都是作者的实践清单，而非 Codex 必须满足的条件。采用时应根据任务耦合度、协调成本、模型与工具负载实测。

05 / 自测

自测：我理解了吗？

先用自己的话回答，再展开参考答案。理解框架不等于接受所有效果数字。

1. 为什么把完整 MCP 工具目录写进 AGENTS.md，不能同时替代“写入”和“选择”？

展开参考答案与对照要点

参考解释：写入只解决信息有稳定载体的问题；若每轮把完整目录都放进窗口，仍会消耗上下文。选择要求只在当前任务需要时加载相关定义。

对照要点：区分“外部存在”与“当前载入”，并指出无关内容的窗口成本。

容易误解：选择不是删除完整目录，而是控制它进入窗口的时机与范围。

回查：四个动作 · 原文（Strategy 1 / Strategy 2）。

2. 自动压缩已经存在，为什么多文件长任务仍可能需要外部计划文件？

展开参考答案与对照要点

参考解释：压缩把历史提炼成摘要，可能省略精确约定或进度；外部计划提供可重新读取、可检查的状态。两者组合比只依赖摘要更稳健。

对照要点：说明压缩有损，以及“写入 + 压缩”的恢复路径。

容易误解：计划文件也会过时，仍需维护；它不是自动正确的永久记忆。

回查：压缩 · 原文（Strategy 3 / The Compounding Effect）。

3. 子代理拥有独立上下文，是否等于它已经获得安全隔离？

展开参考答案与对照要点

参考解释：不等于。独立会话减少信息串扰；工具范围和 profile 限定能力；OS sandbox 才进一步限制文件与系统资源访问。

对照要点：区分上下文组织、能力约束与资源访问控制。

容易误解：不能因为使用了 subagent，就推断它无法访问不相关文件或工具；这取决于配置。

回查：隔离 · 原文（Strategy 4）。

4. 能否把文章的 30,000–40,000 与 100,000 token 数字当作自己项目的可靠切换阈值？

展开参考答案与对照要点

参考解释：不能直接照搬。原文没有提供足以复现和外推的统一实验条件。项目阈值应基于自己的模型、任务、工具负载与质量评价实测。

对照要点：保留证据强度与外推边界。

容易误解：数字证据较弱不等于四策略框架无用；它限制的是效果强度的确定性。

回查：证据边界 · 原文（The Compounding Effect）。
